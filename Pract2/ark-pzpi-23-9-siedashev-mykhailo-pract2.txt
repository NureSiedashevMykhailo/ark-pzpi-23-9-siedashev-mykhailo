ХІД РОБОТИ

Вступ

Рефакторинг - це контрольований процес вдосконалення коду без зміни його зовнішньої поведінки. Він дозволяє боротися з "технічним боргом", покращує структуру програми та полегшує її подальше розширення. У цій роботі розглянуто три методи рефакторингу, які дозволяють оптимізувати розподіл даних між класами, усунути дублювання коду в ієрархіях та виправити помилки неправильного використання успадкування.

Обрані методи:

Move Field (Переміщення поля).

Pull Up Constructor Body (Підйом тіла конструктора).

Replace Inheritance with Delegation (Заміна успадкування делегуванням).

Метод 1: Move Field (Переміщення поля)

Цей метод застосовується, коли поле використовується іншим класом частіше, ніж тим, у якому воно визначене. Це часто трапляється, коли клас розростається і бере на себе забагато відповідальності.

Опис проблеми: У початковій версії коду клас Account містить поле interestRate (відсоткова ставка). Однак логіка нарахування відсотків та сама ставка залежать від типу акаунту (AccountType). Зберігання ставки в Account призводить до дублювання даних, якщо ми захочемо змінити ставку для всіх акаунтів певного типу.

Код до рефакторингу (C++):

class AccountType {
// Тип акаунту просто як маркер
};

class Account {
private:
AccountType* _type;
double interestRate; // Проблема: ставка прив'язана до конкретного акаунту, а не до типу
public:
Account (AccountType* type, double rate) : _type (type), interestRate (rate) {}

double interestForAmount_days (double amount, int days) {
    return interestRate * amount * days / 365;
}


};

Застосування рефакторингу: Ми переміщуємо поле interestRate в клас АccountType i створюємо методи доступу. Тепер Account звертається до ставки через свій тип.

Код після рефакторингу (C++):

class AccountType {
private:
double interestRate; // Поле переміщено сюди
public:
void setInterestRate (double rate) { interestRate = rate; }
double getInterestRate() const { return interestRate; }
};

class Account {
private:
AccountType* _type;
public:
Account (AccountType* type) : _type (type) {}

double interestForAmount_days (double amount, int days) {
    // Звертаємось до ставки через об'єкт типу
    return _type->getInterestRate() * amount * days / 365;
}


};

Переваги:

Покращено когезію (зв'язність) класів: дані знаходяться там, де вони логічно належать.

Спрощено оновлення ставки для групи акаунтів одного типу.

Метод 2: Pull Up Constructor Body (Підйом тіла конструктора)

Цей метод використовується, коли конструктори підкласів мають майже ідентичний код, зазвичай для ініціалізації полів, успадкованих від суперкласу.

Опис проблеми: У нас є базовий клас Employee та підкласи Manager i Engineer. В обох підкласах у конструкторі дублюється код ініціалізації полів name та id, які належать базовому класу. Це порушує принцип DRY (Don't Repeat Yourself).

Код до рефакторингу (С++):

class Employee {
protected:
std::string name;
std::string id;
};

class Manager: public Employee {
int _grade;
public:
Manager (std::string name, std::string id, int grade) {
name = name; // Дублювання
_id = id;    // Дублювання
_grade = grade;
}
};

class Engineer : public Employee {
public:
Engineer (std::string name, std::string id) {
name = name; // Дублювання
_id = id;    // Дублювання
}
};

Застосування рефакторингу: Створюємо конструктор у суперкласі Employee, який ініціалізує спільні поля, і викликаємо його з конструкторів підкласів.

Код після рефакторингу (С++):

class Employee {
protected:
std::string name;
std::string _id;
public:
// Створено конструктор суперкласу
Employee (std::string name, std::string id) : name (name), _id(id) {}
};

class Manager: public Employee {
int _grade;
public:
// Виклик конструктора батьківського класу
Manager (std::string name, std::string id, int grade)
: Employee (name, id), _grade (grade) {}
};

class Engineer : public Employee {
public:
Engineer (std::string name, std::string id)
: Employee (name, id) {}
};

Переваги:

Усунення дублювання коду ініціалізації.

Якщо логіка ініціалізації Employee зміниться, потрібно буде виправити лише одне місце.

Метод 3: Replace Inheritance with Delegation (Заміна успадкування делегуванням)

Цей метод застосовується, коли підклас використовує лише невелику частину функціональності суперкласу або успадкування використовується лише для повторного використання коду, а не для відображення відношення "is-a" (є різновидом).

Опис проблеми: Клас MyStack успадковується від std::vector, щоб використати його сховище. Однак це робить доступними методи вектора (наприклад, insert, erase на довільній позиції), які порушують принцип роботи стеку (LIFO). Це порушення інкапсуляції.

Код до рефакторингу (С++):

#include <vector>

// Проблема: Stack "є" вектором, що дозволяє некоректні операції
class MyStack : public std::vector<int> {
public:
void push (int value) {
this->push_back (value);
}
int pop() {
int val = this->back();
this->pop_back();
return val;
}
};

// Десь у коді:
// MyStack stack;
// stack.insert(stack.begin(), 10); // Помилка дизайну: можна вставити в середину!

Застосування рефакторингу: Замість успадкування, ми робимо вектор полем класу MyStack і делегуємо йому виконання необхідних операцій.

Код після рефакторингу (C++):

class MyStack {
private:
std::vector<int> vector; // Делегування: стек "має" вектор
public:
void push(int value) {
vector.push_back(value);
}
int pop() {
if (vector.empty()) throw std::out_of_range("Stack is empty");
int val = vector.back();
vector.pop_back();
return val;
}
bool isEmpty() const {
return vector.empty();
}
};

Переваги:

Приховано зайві методи суперкласу, які не повинні бути доступні.

Чіткіший інтерфейс класу, що відповідає його призначенню.

Зменшення зв'язності (coupling) між класами.

Інструменти для рефакторингу

Для автоматизації описаних процесів у С++ використовуються такі інструменти:

JetBrains CLion / ReSharper С++: Мають вбудовані функції для безпечного перейменування, переміщення методів/полів та зміни сигнатур.

Clang-Tidy: Дозволяє знаходити місця, які потребують модернізації (наприклад, modern C++ fixes).

SonarQube: Допомагає виявляти дублювання коду та архітектурні проблеми (code smells).

ВИСНОВКИ

У ході виконання роботи було проаналізовано та застосовано три методи рефакторингу: Move Field, Pull Up Constructor Body та Replace Inheritance with Delegation.
Використання цих методів дозволило:

Покращити розподіл відповідальності між класами.

Усунути дублювання коду ініціалізації.

Виправити архітектурну помилку неправильного використання успадкування, зробивши код безпечнішим та зрозумілішим.
Рефакторинг є критично важливим етапом розробки, який перетворює "робочий" код на "якісний" код.
